## 1. 整理与实现原则

1. 用户可以按任意顺序、使用口语描述想法。
2. 每个可独立实现的功能使用稳定编号：`UMA-001`、`UMA-002`……
3. 用户明确说出的内容记为“已确认需求”；合理但未经确认的补充只能记为“实现建议”或“待确认问题”。
4. 不因后续新想法而静默改写旧决定；发生冲突时记录冲突，并在“决策记录”中说明最终选择。
5. 每个功能必须具有可验证的验收标准，避免只写氛围描述。
6. 实现 AI 应优先复用 CK3 原版机制，并记录参考的原版文件和作用域。
7. 所有脚本、事件、本地化键和资源名称统一使用 `uma_` 前缀，除非本文件另有说明。

## 6. 详细实现条目

每个条目使用以下格式。整理需求时复制此模板，不保留无意义的空字段。

### UMA-000：条目名称（模板）

- 状态：待澄清
- 优先级：MVP / 高 / 中 / 低
- 来源：用户口述
- 目标：这个功能要为玩家提供什么体验。
- 已确认需求：
  - 用户明确提出的规则。
- 触发条件：何时检查或启动。
- 前置条件：角色、领地、文化、军队或其他条件。
- 处理流程：
  1. 脚本执行顺序。
- 数值与公式：明确写出基础值、修正来源、上下限和舍入方式。
- 结果：成功、失败及中间结果。
- CK3 实现映射：建议使用的文件目录、脚本类型、作用域和原版参考。
- AI 行为：AI 是否使用、如何评估、是否需要冷却。
- UI 与反馈：玩家能看到的按钮、提示、图标、日志或事件文本。
- 边界情况：死亡、失去领地、军队被消灭、继承、多人游戏、旧存档等。
- 依赖：其他 `UMA-xxx` 条目。
- 验收标准：
  - [ ] 可在游戏内复现并判断通过或失败的条件。
- 实现建议：未经用户确认、但有助于开发的方案。
- 待确认问题：会实质改变实现结果的问题。

## 7. 数据与命名约定

### 7.1 预期目录

- `common/traits/`：马娘身份或成长相关特质。
- `common/men_at_arms_types/`：马娘骑兵兵种。
- `common/character_interactions/`：角色交互。
- `common/decisions/`：玩家主动发起的长期或全局操作。
- `common/modifiers/`：角色、军队、领地等修正。
- `common/scripted_triggers/`：复用条件判断。
- `common/scripted_effects/`：复用执行逻辑。
- `events/`：事件流程与反馈。
- `gfx/interface/icons/`：特质和兵种图标。
- `localization/simp_chinese/`：简体中文本地化。

## 8. 全局非功能要求

### 8.1 兼容性

- 不无理由覆盖原版文件。
- 优先新增条目或使用脚本化逻辑。
- 必须记录无法避免的兼容性冲突。

### 8.2 性能

- 避免无筛选的高频全地图角色遍历。
- 周期性逻辑必须说明执行频率和候选范围。

### 8.3 可维护性

- 重复条件和效果应提取为 scripted trigger/effect。
- 事件、效果和本地化键须能从前缀与编号追溯到实现条目。
